# BF-2129 · 요청/응답 계약 변경표

만료 의미론(경계값 `now >= expiresAt`)의 근거는 `implementation-plan.md` §2를
참조. 아래는 developer(BF-2128)가 그대로 구현해야 하는 계약이다. 기존 필드는
유지하며 신규 필드는 **가산(additive)** 만 한다 — breaking change 없음.

## 1. POST /api/links (링크 생성)

### Request

| 필드 | 타입 | 필수 | 변경 | 설명 |
| --- | --- | --- | --- | --- |
| `targetUrl` | string | Y | 기존 유지 | 리다이렉트 대상 URL |
| `slug` | string | N | 기존 유지 | 사용자 지정 slug |
| `ttlSeconds` | integer | **N (신규)** | 추가 | 링크 유효 기간(초). 미지정 시 무기한 |

- 유효성: `ttlSeconds`가 주어졌는데 정수가 아니거나 `<= 0`이면 요청 전체를
  거부한다.

### Response

| 필드 | 타입 | 변경 | 설명 |
| --- | --- | --- | --- |
| (기존 응답 필드 전부) | - | 기존 유지 | - |
| `expiresAt` | string (ISO 8601) \| null | **추가** | `ttlSeconds` 미지정 시 `null` |

### 상태 코드

| 코드 | 케이스 | 변경 |
| --- | --- | --- |
| `201` | 생성 성공 | 기존 유지, 응답 바디에 `expiresAt` 추가 |
| `400` `INVALID_TTL` | `ttlSeconds`가 0 이하이거나 정수가 아님 | **신규** |

## 2. GET /:slug (리다이렉트 해석)

### 변경 요약

만료된 링크에 대한 요청은 리다이렉트하지 않고 `410 Gone`을 반환한다.
판정 기준은 `now >= expiresAt` (경계값 포함, `implementation-plan.md` §2.2).

### 상태 코드

| 코드 | 케이스 | 변경 |
| --- | --- | --- |
| `302` | 링크 존재 & 미만료 | 기존 유지, 히트 카운트 증가 |
| `404` | 링크 미존재 | 기존 유지 |
| `410` `LINK_EXPIRED` | 링크 존재 & `now >= expiresAt` | **신규** |

### 410 Response Body (신규)

```json
{
  "error": "LINK_EXPIRED",
  "slug": "abc123",
  "expiredAt": "2026-08-15T10:00:00.000Z"
}
```

### 우선순위 (MUST)

`404`(미존재) 판정이 `410`(만료) 판정보다 항상 먼저다 — 존재하지 않는
slug는 만료 여부를 계산하지 않고 즉시 404.

## 3. GET stats (링크 통계 조회)

### Response 변경

| 필드 | 타입 | 변경 | 설명 |
| --- | --- | --- | --- |
| (기존 응답 필드 전부) | - | 기존 유지 | - |
| `expiresAt` | string (ISO 8601) \| null | **추가** | 미보유 레코드는 `null`로 정규화 (`migration.md`) |
| `isExpired` | boolean | **추가** | 응답 시점 기준 재계산 값 (저장된 캐시 값 아님) |

### 상태 코드

| 코드 | 케이스 | 변경 |
| --- | --- | --- |
| `200` | 링크 존재 (만료 여부 무관) | **만료된 링크도 200으로 조회 가능** — 기존 동작에서 만료 개념이 없었으므로 신규 규칙 명시 |
| `404` | 링크 미존재 | 기존 유지 |

만료된 링크에 대해 `stats`가 `404`나 `410`을 반환하지 않는다는 점이 이번
계약의 핵심 결정 사항이다 (통계 조회는 리다이렉트 가능 여부와 독립).

## 4. DELETE /:slug (링크 삭제)

### 변경 요약

만료 여부와 무관하게 기존 동작을 그대로 유지한다 — TTL 도입으로 인한
동작 변경 없음. 명시적으로 문서화하는 이유는 "만료된 링크는 이미 삭제된
것"이라는 오해를 방지하기 위함이다.

### 상태 코드

| 코드 | 케이스 | 변경 |
| --- | --- | --- |
| `204` | 삭제 성공 (링크가 만료 상태여도 동일) | 기존 유지, 명시적 재확인 |
| `404` | 링크 미존재 | 기존 유지 |

## 5. 변경 영향 요약

- 하위호환 파괴 없음 — 모든 변경은 optional 요청 필드 추가 또는 응답
  필드 추가.
- 신규 에러 코드 2종: `400 INVALID_TTL`, `410 LINK_EXPIRED`.
- 기존 데이터(`expiresAt` 필드 없음) 처리 방침은 `migration.md` 참조.
